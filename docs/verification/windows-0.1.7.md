# Labeeb 0.1.7 — local navigation diagnostics

WebView2 NavigationStarting and NavigationCompleted observers capture navigation IDs, redirects, origins, elapsed time, success, native WebErrorStatus and HTTP status (when supported). The first requested navigation is issued only after both observers are attached. Registration/navigation HRESULT failures are logged. Records include a session UUID, tab UUID and timestamp. No automatic retries or error-page suppression were added.

The main-only diagnostics_snapshot command powers More → Diagnostics, refreshed every two seconds while open. Remote pages have no permission to read logs. Only HTTP(S) origins are retained: credentials, paths, query strings, fragments, page content and cookies are excluded. Logs are local in the app data directory as navigation-events.jsonl and navigation-events.previous.jsonl. The active file rotates at approximately 1 MiB; the viewer retains the latest 500 entries across sessions. Persistence errors are displayed. This covers top-level Windows WebView2 navigation, not subresources, application JS errors, Obscura, or macOS navigation.

Validation: TypeScript and 38 frontend tests passed, including a failure followed by success and persistence-error display. All 16 Rust release tests passed, including the real sidecar lifecycle. Native tests and build results are recorded in diagnostics-rust-tests.log and windows-0.1.7-build.log. Rust diagnostics tests verify URL redaction, retention, rotation and restart persistence. The installer remains unsigned; install/uninstall and macOS were not tested.
